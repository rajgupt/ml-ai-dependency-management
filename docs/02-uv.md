## 3 a.m. story

*Your repo has a `requirements.txt`, a `requirements-dev.txt`, an
`environment.yml` that hasn't been touched in a year, a `setup.py`, and a
`Makefile` that calls `conda` and then `pip` in the same shell. Nobody knows
which one is true. The answer is: none of them.*

## 🍳 Recipe 2 — lockfiles that actually reproduce

<!-- WRITE: what makes a lock trustworthy: exact versions, hashes, resolved for every
     platform/python you support (uv.lock is universal — one file, all platforms).

     Table: uv.lock | requirements.txt | requirements.txt --generate-hashes | pylock.toml (PEP 751)
     Columns: hashes? cross-platform? standard? who reads it?

     The CI contract:
       uv sync --frozen   → install from the lock, never re-resolve
       uv sync --locked   → fail if the lock is stale (use this in CI; it catches
                            "I edited pyproject.toml and forgot to re-lock")

     Interop escape hatches for teammates not on uv:
       uv export --format pylock.toml -o pylock.toml
       uv export --no-hashes -o requirements.txt
     Say plainly: these are exports, not sources of truth. Regenerate, never hand-edit. -->

## 🍳 Recipe 3 — dependency groups vs extras

<!-- WRITE: the distinction most teams get wrong.

     [project.optional-dependencies]  → EXTRAS. Ship with your package. Users opt in:
                                        `pip install churnkit[gpu]`. For real features.
     [dependency-groups]              → PEP 735 GROUPS. Never ship. Only for people
                                        working on the repo: dev, docs, lint, typing.

     One-line rule: **extras ship, groups don't.**

     Commands:
       uv add --group dev pytest ruff
       uv add --optional gpu "torch>=2.6"
       uv sync --no-dev            # what your production image installs
       uv sync --all-extras --all-groups
     Note the history briefly: before PEP 735 every tool invented its own dev-deps table
     ([tool.poetry.dev-dependencies], [tool.uv.dev-dependencies], ...). Now there is one
     standard table any tool can read. Prefer it. -->
